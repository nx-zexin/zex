## 一、产品形态：三层，不是一窗

| 层 | 载体 | 何时出现 |
|---|---|---|
| **常驻层** | 托盘图标 + 原生通知 | 始终在。右键菜单可直接下达常用指令 |
| **主窗层** | 主窗口 1280×800，可关可唤回 | 需要看历史、审阅、管理时 |
| **浮层** | 全局快捷键唤起的轻量输入条（`Ctrl+Shift+Z`） | 人在别处，只想扔一句话给它 |

**关键设计判断：主窗关闭 ≠ 退出。**

关窗只收进托盘，内核继续跑（定时任务、文件监听、主动汇报都在工作）。
这是"助理"和"应用"的分水岭——一个必须被打开才能工作的东西，无论多强都还是工具。

## 三、逐区域描述

### 3.1 左侧导航栏（240px）

**上段：品牌与新建**

- 顶部一个琥珀色脉冲圆点 + `ZEX` 字标。圆点有呼吸动画时表示内核正在干活
- `＋ 新会话` 幽灵按钮，悬停时整行浅亮

**中段：会话列表（可滚动）**

- 每条：标题（13px，超出省略）+ 相对时间（11px 次文本，右对齐）
- 当前选中：`#1E232B` 底色 + 左侧 2px 琥珀竖条
- 按时间分组：`今天` / `昨天` / `更早`，分组标题 11px 大字距
- 右键菜单：重命名 / 复制会话 / 导出 / 删除
- **顶部有搜索框**（会话多了必须有，否则找不到）

**下段：七个功能域入口**

| 图标 | 名称 | 内容 |
|---|---|---|
| ⌘ | 对话 | 默认页 |
| ◈ | 记忆 | 它记住了什么，可改可删 |
| ✦ | 技能 | 技能卡片库 |
| ▤ | 知识库 | 文档索引与检索 |
| ◎ | 审计 | 它干过什么（追加式日志） |
| ⛨ | 授权 | 它被允许做什么（可撤销） |
| ⚙ | 设置 | 模型、路径、行为 |

**设计意图**：底部固定导航，点击后**主区切换内容**，不新开窗口。
这样保持"对话为主"，又让所有管理能力可达——避免做成一个臃肿的管理后台。

### 3.2 顶部状态栏（52px）

| 位置 | 内容 |
|---|---|
| 左 | 工作目录（等宽 12px，可点击切换）+ `·` + 模型名 |
| 中 | **模式切换器**：`正常` / `只读`。只读时整条状态栏左侧出现一条琥珀色细线警示 |
| 右 | 累计 token `3.4k/108`（悬停显示估算成本）+ 窗口控制 |

**为什么模式切换要放这么显眼**：它是用户唯一能一键"叫停一切写操作"的开关。
藏在菜单里等于没有——而它恰恰是用户在最紧张时最需要立刻找到的东西。

### 3.3 消息区（核心）

**文档流，不是气泡。**

每条消息：角色标签（11px 大写字距）+ 正文（14px / 行高 1.6）。

为什么不用气泡：Zex 的输出经常是带代码、带工具调用、带长文件路径的内容。
气泡的窄宽度会让这类内容反复折行，可读性远不如通栏文档流。
这是 IDE / 终端气质，不是即时通讯气质——因为它是助理，不是聊天机器人。

#### 五种消息类型

**① 用户消息**

```
USER
帮我看看这个项目怎么跑起来
```

角色标签次文本色，正文主文本色。左侧不加任何竖线（用户不是"系统的一部分"）。

**② 助理消息**

```
ZEX
cargo workspace，12 个 crate。先编译看看。
```

角色标签用琥珀色（唯一区分）。流式输出时末尾有闪烁琥珀光标 `▊`。

**③ 工具调用块**（信息密度的关键）

```
┌─ 工具 ──────────────────────────────── [L2] 有影响 ─┐
│ shell                                                 │
│ $ cargo build --workspace                             │
│ ▸ 正在编译 243 个 crate…                              │
│                                              [展开]   │
└───────────────────────────────────────────────────────┘
```

- 左边缘 3px 竖线，颜色 = 风险等级（灰 / 蓝 / 琥珀 / 红）
- 头部一行：工具名 + 右侧风险胶囊
- 主体：等宽字体，`$` 前缀命令，`▸` 前缀实时输出
  （**执行中只显示最后 3 行**，避免刷屏）
- 执行完成后折叠成两行：结果摘要 + 展开按钮
- 展开后显示完整输出，带复制按钮

**这个块是界面的灵魂。** 用户 90% 的注意力在这里——"它到底在干什么"。
所以设计原则是：默认紧凑、实时但克制、可展开、**颜色即风险**。

**④ 工具结果块**

工具调用块的子节点，左边缘灰色竖线，等宽输出。
失败时：竖线变红、加 ✕ 图标、结果摘要前置"失败"。

**⑤ 系统消息**

```
系统
上下文已压缩（摘要）：18.2k → 4.1k tokens
```

居中、11px、次文本色、两侧细线。
**弱化为"事件"而非"对话"**——它不该和用户的话争夺注意力。

#### 消息区的两个细节

- **当前轮底部有"停止"按钮**（悬浮在右下）。长任务必须有中断手段
- **"从这里重新生成"**：悬停助理消息时出现，允许回到某个历史点分支

### 3.4 审批条（条件出现）

```
⚠ 需要确认                              [L2 有影响]
即将执行 cargo build --workspace
影响：写入 target/ 目录（约 2.1 GB，可撤销）
                       [批准]  [拒绝]  [记住此类]
```

**位置：输入区上方、占满主区宽度。不是模态弹窗。**

理由：模态会切断对话上下文，用户看不到"它为什么问"。
内嵌条保留了来龙去脉——这在审批频繁时对信任的影响是决定性的。

**内容必须回答三个问题**：

1. 要做什么（命令原文，等宽字体）
2. 影响是什么（范围 + 是否可撤销 + 大小估算）
3. 我的选择会产生什么后果

**L3 高危变体**：背景转深红，出现二次确认输入框——必须**手打确认词**才能点批准，
"记住此类"按钮消失。

（对应 `docs/SECURITY.md` §2 的四档模型与 §3.3 的二次确认。）

### 3.5 输入区

```
┌──────────────────────────────────────────────────┐
│ 给 Zex 下达任务…                                  │
│                            @引用文件  📎  🎤      │
└──────────────────────────────────────────────────┘
上下文 12%  ▓▓▓░░░░░░░░░░░░░░░░░░░      [只读] [发送]
```

- **多行自适应**（2–8 行，超出滚动）。`Enter` 发送，`Shift+Enter` 换行
- `@` 唤起文件选择器（把文件内容作为附件而非路径）
- `📎` 粘贴图片（截图直接 `Ctrl+V`）
- **底部上下文占用条**：绿 <60% / 琥珀 60–85% / 红 >85%。
  悬停显示"压缩将在 X% 触发"——把 `docs/ARCHITECTURE.md` §4 的压缩阈值直接暴露给用户
- 流式期间输入框**不锁**——允许用户提前敲下一条，排队

### 3.6 托盘与浮层

**托盘图标**：琥珀圆点。左键唤起主窗；右键菜单：

```
打开 Zex
快速提问        →
暂停主动性      ← 关掉定时任务与主动汇报
只读模式        ✓
─────
正在运行 2 个任务
今天 14 次操作 · 0 次被拒
─────
退出
```

菜单里直接显示"今天 N 次操作"，是让用户对助理的行为量级有持续感知。

**浮层（`Ctrl+Shift+Z`）**：屏幕中央偏上的一条输入框，240px 高。
输入后回车即发，结果在浮层里流式显示，`Esc` 收起。
**适用场景：人在写代码，顺手问一句**，不打断手上的事。

## 四、七个功能面板

主区切换内容，左栏保持不动。

### 4.1 对话（默认）

见 §3.3。

### 4.2 记忆 `◈`

```
┌─────────────────────────────────────────────────────────┐
│ 记忆        [全部] [偏好] [事实] [经验]      🔍 搜索     │
├─────────────────────────────────────────────────────────┤
│ 偏好 · 重要度 高                              [编辑][删] │
│ 用户偏好简短回答，讨厌冗长总结                            │
│ 3 天前 · 命中 12 次                                      │
├─────────────────────────────────────────────────────────┤
│ 经验 · 重要度 中                              [编辑][删] │
│ exp-gpui-wayland-xwayland                                │
│ gpui 在 Wayland 会话下需通过 XWayland 运行…              │
│ 昨天 · 命中 3 次                                         │
└─────────────────────────────────────────────────────────┘
```

- 每条：类型标签 + 重要度 + 正文 + 时间 + 命中次数
- **重要度可拖拽调整**（直接影响召回优先级）
- 可选：切换成"它最近新学了什么"的时间线视图
- **必须能编辑和删除**。黑箱记忆是长期信任的杀手

### 4.3 技能 `✦`

卡片网格，每个卡片：

```
┌────────────────────────┐
│ ✦ gpui-ui              │
│ 用 gpui-kit 构建界面    │
│ ─────────────────────  │
│ 版本 2 · 昨天更新       │
│ 引用 3 次              │
│           [查看] [停用]│
└────────────────────────┘
```

点击进入详情：Markdown 正文只读预览 + "编辑"（打开外部编辑器）+ 版本历史（可回滚）。

**设计意图**：技能是它自己积累的资产，用户要能审阅。
这直接影响"自我进化"这件事的可信度——看不见的进化等于不可控的进化。

### 4.4 知识库 `▤`

左侧文档树 + 右侧检索区：

```
┌──────────────┬──────────────────────────────────────────┐
│ ＋ 添加文档   │ 🔍 输入问题，检索相关片段                │
│              ├──────────────────────────────────────────┤
│ 📁 项目文档   │ 命中 5 段（混合检索：全文 + 向量）       │
│   ▤ README   │                                          │
│   ▤ ARCH…    │ docs/ARCHITECTURE.md · 相似度 0.87       │
│ 📁 论文       │ 「双世界桥接」gpui 的 async executor…    │
│   ▤ …        │                            [查看上下文]  │
└──────────────┴──────────────────────────────────────────┘
```

拖拽文件即入索引。显示索引进度与失败原因。

"混合检索：全文 + 向量"这个标注是刻意暴露的——
对应 `docs/ARCHITECTURE.md` §6 的 RRF 融合，让用户理解为什么精确名词也能搜到。

### 4.5 审计 `◎`

```
┌─────────────────────────────────────────────────────────┐
│ 审计日志    [全部] [只读] [可逆] [有影响] [高危]  📅 今天│
├─────────────────────────────────────────────────────────┤
│ 14:32  [L2] shell        用户批准    成功   cargo build │
│ 14:28  [L0] fs_read      自动        成功   README.md   │
│ 14:15  [L1] fs_write     自动        成功   src/main.rs │
│ 14:15  [L2] shell        用户拒绝    —      rm -rf …    │
└─────────────────────────────────────────────────────────┘
```

- 按时间倒序，风险色标记
- 点击展开：完整参数摘要（脱敏）+ 结果 + 会话链接
- 顶部筛选 + 日期选择 + **导出**
- 右下角固定提示：**"审计日志只能追加，不可修改或删除"**

**这一页是信任的基础。** 用户能回答"它昨天到底干了什么"。
对应 `docs/SECURITY.md` §4 的物理不可篡改（trigger 拒绝 UPDATE/DELETE）。

### 4.6 授权 `⛨`

```
┌─────────────────────────────────────────────────────────┐
│ 它被允许做什么                          [全部撤销]       │
├─────────────────────────────────────────────────────────┤
│ shell · git *                    永久    3 天前  [撤销] │
│ fs_write · /home/adam/projects/** 永久   昨天    [撤销] │
│ shell · npm *                    7 天后过期      [撤销] │
├─────────────────────────────────────────────────────────┤
│ ⚠ 高危操作（格式化、删除系统目录、提权）永不在此列。      │
│    每次都会单独询问。                                    │
└─────────────────────────────────────────────────────────┘
```

**这是"审批可记忆"的反面。**
给了记忆能力，就必须给一览与撤销能力，否则等于永久放权——
那比每次询问更危险，因为它制造了虚假的安全感（`docs/SECURITY.md` §3.1）。

### 4.7 设置 `⚙`

分组纵向表单：

- **模型**：provider、base_url、模型名、密钥（从环境变量读，**只显示变量名**）
- **行为**：默认模式（正常/只读）、审批超时秒数、每轮最大步数
- **路径**：工作目录、配置目录、数据库位置（可打开所在文件夹）
- **主动性**：定时任务列表、开机自启开关、通知开关
- **数据**：导出全部数据、清空记忆、重建索引

### 4.8 任务 `⏱`（M2 后加入）

定时与事件触发的任务列表：

```
每天 09:00  检查 CI 状态并汇总     [启用] 上次 今天 09:00 ✓
文件变化     src/** 变更时跑测试    [停用]
```

每条显示下次执行时间、上次结果、**手动"立即运行"**按钮。

## 五、状态设计（容易被忽略的部分）

| 状态 | 表现 |
|---|---|
| **空会话** | 居中显示 3–4 个建议任务卡片，不是空白页 |
| **流式中** | 光标闪烁 + 输入框右下角"停止" |
| **工具执行中** | 工具块内 `▸` 前缀实时输出末 3 行 + 左侧竖线脉冲 |
| **等待审批** | 审批条滑入（180ms 缓动），托盘图标变琥珀脉冲 |
| **出错** | 消息流内红色块 + 重试按钮，**不弹模态** |
| **网络断开** | 状态栏出现红色"离线"胶囊，输入框禁用发送 |
| **首次启动** | 三步引导：填密钥 → 选工作目录 → 演示一个任务 |

## 七、和当前实现的差距清单

当前 `crates/zex-app/src/bin/zex.rs` 已有的：
单窗口、消息列表（纯文本）、内嵌审批条、单行输入框、发送按钮、
风险标签文字、流式 token 追加。

| 缺失 | 优先级 |
|---|---|
| 左侧导航 + 会话列表 | P0 |
| 工具调用块的独立视觉（现在只是普通消息） | P0 |
| 风险色系（现在只有灰 / 红两色） | P0 |
| 流式光标、停止按钮 | P1 |
| 上下文占用条 | P1 |
| 顶部状态栏（目录 / 模型 / 模式切换） | P1 |
| 七个功能面板 | P1–P2 |
| 托盘 / 浮层 / 通知 | P2 |
| 记忆 / 技能 / 知识库 | P2–M4 |

**建议的改造顺序**：

1. 先做**左侧导航 + 工具块视觉 + 风险色系**
   —— 这三个决定了"像不像最终产品"
2. 再做状态栏与上下文条
3. 最后补功能面板

理由是前三个填的是"结构感"和"信息层级"，
后两类填的是"功能可见性"。结构不对，功能再多也还是原型像。

## 八、附录：视觉令牌

实现时直接抄这些值，比抄长相重要。

### 配色

| 令牌 | 值 | 用途 |
|---|---|---|
| `bg-app` | `#0E1014` | 应用背景 |
| `bg-panel` | `#16191F` | 状态栏、导航、输入区 |
| `bg-code` | `#12151A` | 代码块、参数框 |
| `bg-hover` | `#1E232B` | 悬停 / 选中底色 |
| `border` | `#252A33` | 分割线 |
| `text-primary` | `#E6E8EC` | 正文 |
| `text-muted` | `#8B92A0` | 角色标签、元信息 |
| `brand` | `#E8A33D` | 琥珀金，品牌 + L2 |
| `risk-l0` | `#6B7280` | 只读 |
| `risk-l1` | `#4A9EFF` | 可逆 |
| `risk-l2` | `#E8A33D` | 有影响（同品牌色） |
| `risk-l3` | `#E5484D` | 高危 |
| `ok` | `#3DBFA0` | 成功 |
| `warn-bg` | `#1A1420` | 审批条背景 |
| `danger-bg` | `#1F1216` | L3 审批条背景 |

**风险四色是整个界面的视觉骨架**，其余一律中性灰。
用户扫一眼颜色就知道这次操作有多危险——这是最省认知成本的信息编码。

### 间距与圆角

| 令牌 | 值 |
|---|---|
| 间距基准 | 8px 网格（8 / 16 / 24 / 32） |
| 圆角 · 代码块 | 6px |
| 圆角 · 面板 | 8px |
| 圆角 · 输入框 | 10px |
| 圆角 · 胶囊/按钮 | 全圆 |
| 投影 | 不超过 4px 模糊，几乎不可见 |

### 字体

| 用途 | 字族 | 字号 |
|---|---|---|
| 正文 | Noto Sans CJK SC（Win: Microsoft YaHei / macOS: PingFang SC） | 14px / 行高 1.6 |
| 角色标签 | 同上 | 11px / 字距 +0.08em / 大写 |
| 路径·命令·代码 | JetBrains Mono / SF Mono | 12px |
| 标题 | 同上正文 | 14px 加粗 |

字体在 Linux 上必须显式设置：默认的 `.SystemUIFont` 解析不到，
会回退到 `Segoe UI`（Windows 字体），中文渲染成方框。
代码里已有 `apply_platform_font()`，可用 `ZEX_UI_FONT` 覆盖。

### 动效

| 场景 | 时长 / 曲线 |
|---|---|
| 审批条滑入 | 180ms `ease-out` |
| 工具块展开/折叠 | 150ms `ease-in-out` |
| 状态圆点呼吸 | 2s 循环 |
| 流式光标闪烁 | 1s 循环 |

刻意克制：动效只用于"状态变化提示"，不用于装饰。
长期盯着的东西，动得越少越好。
